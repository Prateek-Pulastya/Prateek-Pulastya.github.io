GuardRail-as-a-Service

A filter that sits in front of a production LLM and decides, per request, whether the prompt is safe to forward. Tier 1 is a deterministic Aho-Corasick and regex matcher that handles the common case in under 0.1 ms. Tier 2 is a DeBERTa-v3 classifier that only ever sees what Tier 1 passes. The interesting part is not the speed; it is that I can tell you exactly how well it works, including where it doesn't.

Caveats

Tier 1's blocklist was tuned by looking at the attacks it missed on my own corpus, so its 1.000 in-sample recall is partly just memorisation. I split the corpus 60/40, refit the rules on the training half, and scored the rest: 0.7895. That is the number I quote. If I led with the in-sample 1.00 instead, I would be overstating the result by 21 points. The repo says this in its README, labels the contaminated row “not a result”, and keeps every figure as reproducible JSON under results/.

Tier 2 ships monitor-only

On the NotInject over-defense benchmark the classifier blocks 40.4% of benign prompts against Tier 1's 0.0%, and that over-blocking is not threshold-separable. So Tier 2 scores and logs a TIER2-FLAG but does not block. That costs recall, which I say out loud rather than hide; the blocking mode is still reachable at POST /validate?tier=2.

Double scan, and fail open

Tier 1 scans normalised text first, keeping | _ - so markers like <|im_start|> still match, then a de-leeted, separator-stripped pass, which is what catches 1gn0r3 prev10us 1nstruct10ns. If the Tier 2 model errors, the request is allowed through. That is a deliberate choice: availability over coverage.

Run Tier 1 in your browser

A faithful reimplementation of the Tier 1 logic: normalise (keeping | _ -), then a de-leeted, separator-stripped second pass. It runs entirely client-side; nothing leaves your browser. The production service adds the monitor-only DeBERTa-v3 Tier 2; this is the deterministic layer only.

This is not “7× better than LlamaGuard”. Llama-Guard-3 is a content-safety classifier; its S1–S13 taxonomy does not include prompt injection, so it missed 165 of 190 attacks because it was never built to catch them. The fair claim is narrower: content-safety guardrails do not transfer to prompt-injection detection. CloudFracture

A deliberately vulnerable LLM-agent workload on AWS, built as Terraform, then compromised along four identity-based paths, from the agent's execution role out to data exfiltration and prompt-store poisoning. Each path gets a tested Sigma detection; the IAM is then rewritten to least-privilege and the same attacks re-run to prove they now fail. The whole thing ships through CI with SAST, SCA, secret and IaC scanning, and an SBOM.

ATSGuard

Catches indirect prompt injection in résumés: the white-on-white instruction hidden in a CV to hijack an LLM-based applicant tracking system. A four-layer pipeline reads the styling, not just the text, strips invisible Unicode and homoglyphs, and routes each file allow / flag / block. It holds 0% false positives across 1,200 résumés. In-sample recall is 98.8%; on a held-out split it drops to 42.9%, which is the figure I report.

Sandbox escape in smolagents

A code-injection flaw in the agent execution sandbox let arbitrary commands run on the host, the exact boundary an agentic framework exists to hold. Disclosed to the maintainers.

HighDetection bypass · via Intigriti

Path-traversal bypass in Aikido firewall-java

A payload that slipped past the WAF's traversal detection while staying a working traversal: a security control failing open against the one class it advertises.

CriticalClosed: duplicate (valid)

CORS origin reflection → account takeover

A REST API reflected any attacker-supplied Origin verbatim while returning Access-Control-Allow-Credentials: true, with the session cookie scoped to the root domain and no HttpOnly. One visit to a malicious page silently pulled profile data, API keys and marketing contact databases as the logged-in user. Fix: a server-side origin allowlist at the gateway, with HttpOnly as defence in depth.

CriticalClosed: duplicate (confirmed valid)

Unauthenticated GraphQL user enumeration: 57M records

Introspection was off, but validation-error field enumeration exposed a Relay-style users connection that took cursor pagination unauthenticated, with no rate limiting and no depth cap. totalCount returned 57,316,627, which I confirmed live against a 209,852-account delta over eight days. A full export was reachable in roughly 32 hours at a conservative 10 req/s.

HighTriaged duplicate · P4

Unrestricted Google Maps API keys in page source

Two keys were hardcoded into served HTML and a webpack bundle, both issued with no referrer, IP or API restriction, extractable with a single unauthenticated curl. A controlled 50-request test returned 50/50 OK with no throttling, which works out to roughly $121/hour of billable abuse from one workstation. CWE-798; OWASP API4:2023.

InformativeClosed: theoretical exploitability

Dangling Route53 delegation → subdomain takeover

Certificate-transparency logs surfaced a staging subdomain with live NS delegation into an abandoned Route53 zone (SOA serial=1). Because Route53 hands deleted zones' nameservers back to a shared pool, any AWS account could reclaim authority, and the root-scoped session cookie would have made that directly exploitable. Of 11 NXDOMAIN candidates I checked via passive DNS and Wayback CDX, exactly one was still delegated.
